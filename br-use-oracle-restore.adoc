= Wiederherstellung von Oracle-Datenbank-Workloads mit NetApp Backup und Recovery
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Oracle Database-Workloads lassen sich aus Snapshots, replizierten Backups auf Sekundärspeicher oder in Objektspeicher gespeicherten Backups mit NetApp Backup and Recovery wiederherstellen.

.Von diesen Speicherorten wiederherstellen
Sie können Datenbanken von verschiedenen Startorten wiederherstellen:

* Wiederherstellung von einem primären Standort (lokaler Snapshot)
* Wiederherstellen von einer replizierten Ressource auf einem sekundären Speicher
* Wiederherstellung aus einer Objektspeichersicherung


.Stellen Sie diese Punkte wieder her
Sie können eine Datenbank an ihrem ursprünglichen Speicherort wiederherstellen oder sie als neue Datenbank auf einem anderen registrierten Host (alternativer Speicherort) wiederherstellen.

* Am ursprünglichen Speicherort wiederherstellen
* Wiederherstellung an einem alternativen Speicherort (einem anderen registrierten Host)




[[how-oracle-database-restore-works]]
== Wie die Wiederherstellung einer Oracle Database funktioniert

Beim Wiederherstellen von Oracle Database Workloads geschieht Folgendes:

* Wenn Sie eine Datenbank aus einem lokalen Snapshot wiederherstellen, erstellt NetApp Backup and Recovery eine _neue_ Ressource mithilfe der Daten aus dem Backup.
* Wenn Sie aus einem replizierten Speicher wiederherstellen, können Sie es am ursprünglichen Speicherort wiederherstellen.
* Wenn die Wiederherstellung an einem alternativen Speicherort erfolgt, stellt NetApp Backup and Recovery die ausgewählte Sicherung der Quelldatenbank als neue Datenbank auf einem anderen registrierten Host wieder her. Sie geben den Zielhost und einen Namen für die neue Datenbank an. Wenn Sie keine Wiederherstellungsspezifikationsdatei angeben, berechnet Backup and Recovery automatisch die Speicherorte für die Datendateien, Kontrolldateien und Wiederherstellungsprotokolldateien auf dem Zielhost.
* Wenn Sie ein Backup aus dem Objektspeicher wiederherstellen, können Sie die Daten im Quellspeicher oder auf einem lokalen ONTAP -System wiederherstellen und die Datenbank von dort wiederherstellen.




[[view-information-about-available-oracle-database-restore-points]]
== Informationen zu verfügbaren Wiederherstellungspunkten der Oracle Database

Verfügbar sind die Wiederherstellungspunkte einschließlich der SCN-Nummer und der zugehörigen Datenbankinkarnation.


NOTE: Oracle Database erstellt jedes Mal eine neue Datenbankinkarnation, wenn Sie eine Datenbank mit der  `RESETLOGS` Option öffnen. NetApp Backup and Recovery listet die relevanten Datenbankinkarnationen auf, wenn Sie Wiederherstellungspunkte überprüfen und wenn Sie eine Wiederherstellung bis zu einer bestimmten SCN durchführen.

.Schritte
. Im Menü „Backup and Recovery“ erfolgt die Auswahl von *Inventory*.
. Wählen Sie im NetApp Backup and Recovery -Menü *Wiederherstellen* aus.
. Für die Oracle Database Workload ist *Ansicht* auszuwählen.
. Wählen Sie die Registerkarte *Datenbanken*.
. Wenn die Wiederherstellungspunkte einer Datenbank angezeigt werden sollen, ist für diese Datenbank das *Aktionen* image:icon-action.png["Symbol „Aktionen“"] Symbol und anschließend *Schutzdetails anzeigen* auszuwählen.
. Die verfügbaren Wiederherstellungspunkte sowie die jeweils zugehörige SCN-Nummer und Datenbankinkarnation werden überprüft.




[[restore-an-oracle-database]]
== Wiederherstellen einer Oracle-Datenbank

Je nach Bedarf lässt sich eine Oracle Datenbank auf einen bestimmten Zeitpunkt, eine bestimmte Systemänderungsnummer (SCN) oder den letzten funktionierenden Zustand wiederherstellen. Die Datenbank kann auch aus Snapshots wiederhergestellt werden, wobei der automatisierte Wiederherstellungsprozess übersprungen werden kann, zum Beispiel wenn die Wiederherstellung manuell erfolgen soll. Die Datenbank lässt sich anhand ihres Namens oder mit spezifischen Filtern suchen.

*Erforderliche NetApp Console-Rolle* Backup und Recovery Super-Admin- oder Backup und Recovery Restore-Admin-Rolle https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["Erfahren Sie mehr über die Zugriffsrollen der NetApp Console für alle Dienste"^].

[[alternate-location-support]]
.Bevor Sie beginnen
Bei einer Wiederherstellung an einem alternativen Speicherort sind die folgenden unterstützten und nicht unterstützten Wiederherstellungsszenarien zu beachten:

*Unterstützte Wiederherstellungsszenarien für alternative Standorte*

* Wiederherstellen einer einzelnen, vollständigen Oracle Datenbank auf einem einzelnen Zielhost
* Wiederherstellung zu einem bestimmten Zeitpunkt, zu einer bestimmten SCN oder zum letzten Backup
* Verwendung externer Archivprotokollverzeichnisse, wenn die für den ausgewählten Wiederherstellungspunkt erforderlichen Archivprotokolle nicht in der Sicherung enthalten sind


*Nicht unterstützte Szenarien für die Wiederherstellung an einem alternativen Speicherort*

* Wiederherstellung nur von Tablespaces, einschließlich der Wiederherstellung von Tablespaces innerhalb einer PDB
* Wiederherstellung nur der PDB in eine andere Containerdatenbank (CDB)
* Wiederherstellung aus dem sekundären Storage
* Wiederherstellung aus dem Objektspeicher


[NOTE]
====
Wenn PDBs oder Tablespaces zu einem bestimmten Zeitpunkt oder SCN wiederhergestellt werden:

* Wählen Sie nur eine PDB aus. Zeitpunktgenaue Wiederherstellung ist nicht mit der Wiederherstellung mehrerer PDBs kompatibel.
* `PDB$SEED`Kann nicht für zeitpunktgenaue Wiederherstellung ausgewählt werden.
* Die Wiederherstellung von Kontrolldateien kann nicht mit zeitpunktgenauem Recovery von PDBs oder PDB-Tablespaces kombiniert werden.
* Die  `SYSTEM`, `SYSAUX` und  `UNDO` Tabellenbereiche können nicht ausgewählt werden.


====
.Schritte
. Wählen Sie im NetApp Console *Schutz > Sicherung und Wiederherstellung*.
. Wählen Sie im NetApp Backup and Recovery -Menü *Wiederherstellen* aus.
. Wählen Sie aus der Dropdown-Liste rechts neben dem Namenssuchfeld *Oracle* aus.
. Geben Sie den Namen der Datenbank ein, die Sie wiederherstellen möchten, oder filtern Sie nach dem Datenbankhost, auf dem sich die wiederherzustellende Datenbank befindet.
+
Es wird eine Liste mit Snapshots angezeigt, die Ihren Suchkriterien entsprechen.

. Wählen Sie die Schaltfläche *Wiederherstellen* für die Datenbank, die Sie wiederherstellen möchten.
. Wählen Sie eine Wiederherstellungsoption:
+
[role="tabbed-block"]
====
.Wiederherstellung zu einem bestimmten Zeitpunkt
--
.. Wählen Sie *Zu einem bestimmten Zeitpunkt wiederherstellen*.
.. Wählen Sie *Weiter*.
.. Wählen Sie ein Datum aus der Dropdown-Liste und wählen Sie *Suchen*.
+
Die der angegebenen Uhrzeit und dem angegebenen Datum nächstliegende Snapshot wird angezeigt.

.. Wenn der Snapshot an mehr als einem Ort gespeichert ist, kann ein Quellort ausgewählt und Standortdetails hinzugefügt oder überprüft werden.
.. Wählen Sie *Weiter*.


--
.Wiederherstellen auf eine bestimmte Systemänderungsnummer (SCN)
--
.. Optional sind in <<Informationen zu verfügbaren Wiederherstellungspunkten der Oracle Database>> die verfügbaren SCNs und zugehörigen Datenbank-Inkarnationen aufgeführt.
.. Wählen Sie *Auf eine bestimmte Systemänderungsnummer (SCN) wiederherstellen*.
.. Wählen Sie *Weiter*.
.. Geben Sie die SCN ein, die als Wiederherstellungspunkt verwendet werden soll, und wählen Sie *Suchen*.
+
Der am besten passende Snapshot für die angegebene SCN wird angezeigt. Falls mehrere Datenbankinkarnationen mit der SCN übereinstimmen, werden alle übereinstimmenden Inkarnationen angezeigt.

.. Wenn mehrere Datenbankinkarnationen der Suche entsprechen, muss der Snapshot mit der richtigen Inkarnation ausgewählt werden.
.. Wenn der Snapshot an mehr als einem Ort gespeichert ist, kann ein Quellort ausgewählt und Standortdetails hinzugefügt oder überprüft werden.
.. Wählen Sie *Weiter*.


--
.Wiederherstellen auf die letzte Sicherung (letzter guter Zustand)
--
.. Wählen Sie *Auf die neueste Sicherung wiederherstellen*.
.. Wählen Sie *Weiter*.
+
Der aktuellste Snapshot wird angezeigt. Der Wiederherstellungsvorgang stellt den letzten funktionierenden Zustand mithilfe aller verfügbaren Protokollsicherungen wieder her.

.. Wenn der Snapshot an mehr als einem Ort gespeichert ist, kann ein Quellort ausgewählt und Standortdetails hinzugefügt oder überprüft werden.
.. Wählen Sie *Weiter*.


--
.Wiederherstellen aus Snapshots ohne Wiederherstellung
--
.. Wählen Sie *Aus Snapshots ohne Wiederherstellung wiederherstellen*.
+
Die Auswahl dieser Option bedeutet, dass die Datenbank aus Snapshots wiederhergestellt wird, das Recovery jedoch übersprungen wird (Protokollsicherungen werden nicht angewendet).

.. Wählen Sie *Weiter*.
+
Verfügbare Snapshots werden angezeigt.

.. Einen Snapshot aus der Liste auswählen und *Weiter* wählen.
.. Wenn der Snapshot an mehr als einem Ort gespeichert ist, kann ein Quellort ausgewählt und Standortdetails hinzugefügt oder überprüft werden.
.. Wählen Sie *Weiter*.


--
====
. Wählen Sie das Wiederherstellungsziel und die Einstellungen aus:
+
[role="tabbed-block"]
====
.Am ursprünglichen Speicherort wiederherstellen
--
.. Im Abschnitt *Zieleinstellungen* sind folgende Schritte auszuführen:
+
... Für RAC-Datenbanken den RAC-Knoten auswählen, auf dem die Wiederherstellung ausgeführt werden soll. Diese Option erscheint nur für RAC-Datenbanken.
... Wählen Sie aus, was wiederhergestellt werden soll:
+
**** *Alle Datendateien* kann ausgewählt werden, um die gesamte Datenbank oder Containerdatenbank (CDB) wiederherzustellen.
**** *Pluggable Databases (PDBs)* kann ausgewählt werden, um eine oder mehrere PDBs aus einer CDB wiederherzustellen, ohne die anderen PDBs im Container zu beeinträchtigen. Anschließend werden die gewünschten PDBs aus der Liste ausgewählt.
**** *Pluggable database (PDB) Tablespaces* (bei einer Nicht-CDB Datenbank als *Tablespaces* angezeigt) auswählen, um bestimmte PDB Tablespaces wiederherzustellen. Anschließend die PDB und die Tablespaces auswählen.


... Optional kann die Option *Steuerdateien* aktiviert werden, um auch die Datenbank-Steuerdateien wiederherzustellen. Diese Option kann nicht für zeitpunktgenaue oder SCN-basierte Wiederherstellung von PDBs oder PDB-Tablespaces ausgewählt werden.
... Optional kann die Option *Datenbankstatus bei Bedarf für Wiederherstellung und Recovery ändern* aktiviert werden, damit Backup and Recovery den Datenbankstatus je nach Art der Wiederherstellung verwalten kann.
... Optional kann die Option *Wiederherstellung vor Ort erzwingen* aktiviert werden, um eine Wiederherstellung vor Ort durchzuführen, wenn nach der Sicherung neue Datendateien hinzugefügt wurden oder wenn LUNs in einer LVM-Festplattengruppe hinzugefügt, gelöscht oder neu erstellt wurden. Dadurch wird die Prüfung auf fremde Dateien umgangen; die Datenbank-Recovery wird mit der von Ihnen ausgewählten Wiederherstellungsoption fortgesetzt.
... Im Feld *Specify external archive log files locations* werden die Speicherorte externer Archivprotokolldateien angegeben, wenn eine Datenbank zu einem bestimmten Zeitpunkt oder SCN wiederhergestellt wird und sich die Archivprotokolle nicht am konfigurierten Speicherort befinden. Anzugeben sind ein Dateisystempfad, der mit `/` beginnt, oder eine ASM Festplattengruppe, die mit `+` beginnt. Mit den Schaltflächen „Plus“ und „Minus“ neben dem Texteingabefeld lassen sich Speicherorte hinzufügen oder entfernen. Dieses Feld wird nicht angezeigt, wenn aus Snapshots ohne Recovery wiederhergestellt wird.
... Optional kann die Option *Datenbank oder Containerdatenbank nach der Wiederherstellung im READ-WRITE-Modus öffnen* aktiviert und eine Unteroption ausgewählt werden, die dem Wiederherstellungsbereich entspricht (diese Optionen werden nicht angezeigt, wenn aus Snapshots ohne Recovery wiederhergestellt wird):
+
**** *Alle Datendateien*: Die Datenbank oder Containerdatenbank wird nach dem Datenbank-Recovery im READ-WRITE-Modus geöffnet.
**** *PDBs oder PDB-Tablespaces*: Nach der Wiederherstellung die Pluggable Databases im READ-WRITE-Modus öffnen.
**** *Nicht-CDB-Tablespaces*: Die Tablespaces werden nach der Wiederherstellung wieder online geschaltet.




.. Im Abschnitt *Präskripte und Postskripte* sind folgende Schritte auszuführen:
+
... *Vorgabe*: Optional kann diese Option aktiviert und der vollständige Pfad zu einem Skript angegeben werden, das vor dem Wiederherstellungsvorgang ausgeführt werden soll, sowie alle Argumente, die das Skript benötigt.
... *Postscript*: Aktivieren Sie diese Option optional und geben Sie den vollständigen Pfad für ein Skript ein, das nach dem Wiederherstellungsvorgang ausgeführt werden soll, sowie alle Argumente, die das Skript verwendet.
... Wählen Sie einen Zeitüberschreitungswert für das Skript. Falls das Skript innerhalb dieses Zeitraums nicht ausgeführt werden kann, wird die Wiederherstellung dennoch fortgesetzt.




--
.An einem anderen Speicherort wiederherstellen
--
Wiederherstellung einer Datenbank als neue Datenbank auf einem anderen registrierten Host. Überprüfung der <<alternate-location-support,Unterstützte und nicht unterstützte Szenarien>> vor Beginn.

+
... *Zielhost*: Auswahl des registrierten Hosts, auf dem Sie die neue Datenbank erstellen möchten.
... *Ziel-Datenbank*: Der Name für die Ziel-Datenbank wird eingegeben. Standardmäßig beginnt der Name mit dem Namen der Quelldatenbank, er kann jedoch bearbeitet werden.
... *Zieldatenbankparameter anpassen*: Mit dieser Option kann eine benutzerdefinierte Wiederherstellungsspezifikationsdatei hochgeladen werden, um die Parameter der Zieldatenbank anzupassen.
... *Wiederherstellungsspezifikationsdatei*: Wenn Sie die Option *Zieldatenbankparameter anpassen* aktiviert haben, geben Sie eine Wiederherstellungsspezifikationsdatei an, um festzulegen, wo die wiederhergestellten Dateien auf dem Zielhost abgelegt werden. Sie können eine Standard-Wiederherstellungsspezifikationsdatei herunterladen und anpassen, um die Details der Zieldatenbank wie Authentifizierung und Protokollspeicherorte zu ändern.
+
Wenn Sie keine Wiederherstellungsspezifikationsdatei angeben, berechnet Backup and Recovery automatisch die Speicherorte für die Datendateien, Kontrolldateien und Wiederherstellungsprotokolldateien.

... Dieses Feld wird nicht angezeigt, wenn aus Snapshots ohne Recovery wiederhergestellt wird.

--
====
. Wählen Sie *Wiederherstellen*.
+
Nach Abschluss der Wiederherstellung können Sie auf der Seite *Inventar* prüfen, ob die neue Datenbank aufgeführt ist. Falls die Datenbank nicht aufgeführt ist, können Sie den Zielhost aktualisieren.
