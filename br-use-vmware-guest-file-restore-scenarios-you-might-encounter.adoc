= Fehlerbehebung bei der Wiederherstellung von VMware-Gastdateien in NetApp Backup and Recovery
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Sollten beim Wiederherstellen einer Gastdatei Probleme auftreten, können diese Szenarien zur Identifizierung und Behebung des Problems herangezogen werden.



[[guest-file-restore-session-is-blank]]
== Die Gastdateiwiederherstellungssitzung ist leer

Dieses Problem tritt auf, wenn Sie eine Gastdatei-Wiederherstellungssitzung erstellen und das Gastbetriebssystem während der Sitzung neu startet. VMDKs im Gastbetriebssystem könnten offline bleiben, sodass die Liste der Wiederherstellungssitzungen für Gastdateien leer ist.

Zur Behebung des Problems werden die VMDKs im Gastbetriebssystem manuell wieder online geschaltet. Sobald die VMDKs online sind, zeigt die Gastdateiwiederherstellungssitzung die korrekten Inhalte an.



[[guest-file-restore-attach-disk-operation-fails]]
== Der Vorgang zum Anhängen der Festplatte beim Wiederherstellen der Gastdatei schlägt fehl

Dieses Problem tritt auf, wenn eine Wiederherstellung von Gastdateien gestartet wird, der Vorgang zum Einbinden der Festplatte jedoch fehlschlägt, obwohl VMware Tools ausgeführt wird und die Anmeldeinformationen des Gastbetriebssystems korrekt sind. Tritt dies auf, wird die folgende Fehlermeldung zurückgegeben:

`Error while validating guest credentials, failed to access guest system using specified credentials: Verify VMware Tools is running properly on the system and that the account used is an Administrator account. Error is SystemError vix error codes = (3016, 0).`

Um das Problem zu beheben, den VMware Tools Windows-Dienst auf dem Gastbetriebssystem neu starten und anschließend die Gastdateiwiederherstellung erneut versuchen.



[[backups-are-not-detached-after-guest-file-restore-session-is-discontinued]]
== Sicherungen werden nicht getrennt, nachdem die Gastdateiwiederherstellungssitzung abgebrochen wurde

Dieses Problem tritt auf, wenn Sie einen Gastdateiwiederherstellungsvorgang aus einer VM-konsistenten Sicherung durchführen. Während die Gastdateiwiederherstellungssitzung aktiv ist, wird eine weitere VM-konsistente Sicherung für dieselbe VM durchgeführt. Wenn die Gastdateiwiederherstellungssitzung entweder manuell oder automatisch nach 24 Stunden getrennt wird, werden die Sicherungen für die Sitzung nicht getrennt.

Um das Problem zu beheben, trennen Sie die VMDKs, die an die aktive Gastdateiwiederherstellungssitzung angehängt waren, manuell.
