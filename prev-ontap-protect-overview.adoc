= Schutz von ONTAP Volumes Workloads mit NetApp Backup and Recovery
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
NetApp Backup und Recovery schützt und stellt Ihre ONTAP Volume-Daten wieder her und archiviert Backups langfristig. Eine 3-2-1-Strategie kann umgesetzt werden, bei der drei Kopien Ihrer Quelldaten auf zwei verschiedenen Speichersystemen und eine Kopie in der Cloud vorhanden sind.

Nachdem Sie den Schutz für ein System aktiviert haben, erstellt Backup and Recovery fortlaufend inkrementelle Kopien Ihrer Volumes auf Blockebene. Zusätzlich zu Ihrem Quellvolume stehen Ihnen folgende Volumes zur Verfügung:

* Eine Momentaufnahme des Volumens auf dem Quellsystem
* Ein repliziertes Volume auf einem anderen ONTAP Storage-System
* Eine Sicherung des Volumes im Objektspeicher


image:diagram-321-overview-unified.png["Ein Diagramm, das zeigt, wie Sicherungsdateien auf dem Quellsystem als Snapshots, als replizierte Volumes auf dem sekundären Storage-System und als Sicherungsdateien im Objektspeicher existieren."]

Der 3-2-1-Ansatz bietet folgende Vorteile:

* Mehrere Datenkopien schützen vor internen und externen Cybersicherheitsbedrohungen.
* Die Verwendung unterschiedlicher Medientypen erleichtert Ihnen die Wiederherstellung, wenn ein Typ ausfällt.
* Sie können die Wiederherstellung schnell von der Vor-Ort-Kopie durchführen und die Offsite-Kopien verwenden, wenn die Vor-Ort-Kopie kompromittiert ist.


Bei Bedarf können Sie ein gesamtes _Volume_, einen _Ordner_ oder eine oder mehrere _Dateien_ von einer beliebigen Kopie auf dasselbe oder ein anderes System wiederherstellen.



[[how-protection-for-ontap-volumes-works]]
== Wie der Schutz von ONTAP Volumes funktioniert

Wenn Sie Backup and Recovery für ein Cloud Volumes ONTAP oder lokales ONTAP System aktivieren, führt der Dienst einen vollständigen Basistransfer Ihrer Volume-Daten durch. Anschließend erfolgen alle Übertragungen inkrementell: Es werden nur geänderte und neue Blöcke übertragen, wodurch der Netzwerkverkehr auf ein Minimum reduziert wird.

Backup and Recovery nutzt ONTAP SnapMirror Technologie, um Ihre Kopien synchron zu halten. Es erstellt Snapshots auf dem Quellvolume und überträgt sie an die Replikations- und Backup-Speicherorte. Backup auf Objektspeicher basiert auf https://docs.netapp.com/us-en/ontap/concepts/snapmirror-cloud-backups-object-store-concept.html["NetApp SnapMirror Cloud-Technologie"^].

image:diagram-backup-recovery-general.png["Ein Diagramm, das zeigt, wie NetApp Backup and Recovery mit den Volumes auf den Quellsystemen und dem sekundären Speichersystem sowie dem Zielobjektspeicher kommuniziert, wo sich die replizierten Volumes und Sicherungsdateien befinden."]

Dieses Diagramm zeigt Volumes, die auf ein Cloud Volumes ONTAP System repliziert werden, aber Volumes können auch auf ein lokales ONTAP System repliziert werden.

Jeder Kopiertyp befindet sich an einem anderen Ort:

* _Snapshots_ befinden sich auf dem Quellvolume im Quellsystem.
* _Replizierte Volumes_ befinden sich auf dem sekundären Storage-System, bei dem es sich um ein Cloud Volumes ONTAP oder ein on-premises ONTAP System handeln kann.
* _Sicherungskopien_ befinden sich in einem Objektspeicher in Ihrem Cloud-Konto oder in Ihren Räumlichkeiten. Die Console erstellt für jeden Cluster einen Objektspeicher. Details dazu, wie die Console den Objektspeicher erstellt und benennt, finden Sie unter link:concept-backup-to-cloud.html#where-backups-reside-in-object-store-locations["Wo sich Backups in Objektspeicherorten befinden"].



CAUTION: Das direkte Managen oder Ändern von Sicherungsdateien in Ihren Storage-Systemen oder in der Umgebung Ihres Cloud-Providers ist zu vermeiden. Andernfalls können die Dateien beschädigt werden, und es entsteht eine nicht unterstützte Konfiguration.

Informationen zur Planung, welche Kopien und welche Architektur verwendet werden sollen, finden Sie unter link:prev-ontap-protect-journey.html["Planung des ONTAP Volume-Schutzes"].



[[features]]
== Features

*Replikation*

* Replizieren Sie Daten zwischen ONTAP -Speichersystemen, um Backup und Disaster Recovery zu unterstützen.
* Replizieren Sie mehrere FlexVol -Volumes gleichzeitig auf ein sekundäres System.
* Zwischen den beiden Systemen kommt die native ONTAP Verschlüsselung während der Übertragung mit einem vorab freigegebenen Schlüssel (PSK) zum Einsatz.
* Die Replikation bietet im Falle eines Übertragungsfehlers Selbstreparatur.
* Die Wiederherstellung eines replizierten Volumes auf dem Quellsystem oder auf einem anderen System ist möglich.


Informationen zu Funktionen in https://docs.netapp.com/us-en/data-services-replication/index.html["NetApp Replication"^], die bei der Replikation mit Backup and Recovery nicht verfügbar sind, finden sich unter link:br-reference-limitations.html#replication-limitations-for-ontap-volumes["Replikationsbeschränkungen für ONTAP -Volumes"].

*Backup in Objektspeicher*

* Unabhängige Kopien Ihrer Volumes werden in kostengünstigem Objektspeicher gesichert, von lokalen oder Cloud-Systemen in eine öffentliche oder Private Cloud.
* Eine einheitliche Sicherungsrichtlinie kann auf alle Volumes in einem Cluster angewendet werden, Volumes mit unterschiedlichen Wiederherstellungspunktzielen können verschiedene Richtlinien zugewiesen werden, oder es kann eine Richtlinie erstellt werden, die für alle zukünftigen Volumes im Cluster gilt. Weitere Informationen finden Sie unter link:prev-ontap-policy-manage.html["Richtlinien für ONTAP Volumes managen"].
* Mit DataLock und Ransomware-Scans lassen sich Ihre Backups vor Löschung und Ransomware schützen. Weitere Informationen finden Sie unter link:prev-ontap-policy-object-options.html#datalock-and-ransomware-protection-options["DataLock- und Ransomware-Schutzoptionen"].
* Ältere Backups lassen sich zur Kosteneinsparung in Archiv-Storage auslagern. Weitere Informationen finden Sie unter link:prev-ontap-policy-object-options.html#archival-storage-options["Archivspeicheroptionen"].
* Durch das Löschen der Sicherungsbeziehung können Quellvolumes außer Betrieb genommen werden, während deren Sicherungen erhalten bleiben.
* Bis zu 4.000 Backups eines einzelnen Volumes beibehalten.
* Backup-Daten lassen sich mit AES-256-Bit-Verschlüsselung im Ruhezustand und TLS 1.2 HTTPS-Verbindungen während der Übertragung sichern, alternativ können anstelle der Standardschlüssel des Cloud-Anbieters eigene, kundenseitig verwaltete Schlüssel verwendet werden.


*Wiederherstellen*

* Wiederherstellung von Daten ab einem bestimmten Zeitpunkt aus lokalen Snapshots, replizierten Volumes oder Backups im Objektspeicher.
* Wiederherstellen eines Volumes, eines Ordners oder einzelner Dateien auf dem Quellsystem oder auf einem anderen System, einschließlich eines Systems, das ein anderes Abonnement oder Konto verwendet oder sich in einer anderen Region befindet.
* Eine _schnelle Wiederherstellung_ eines Volumes aus dem Objektspeicher auf ein Cloud Volumes ONTAP oder ein On-Premises-System ist möglich, wenn der Zugriff auf das Volume so schnell wie möglich bereitgestellt werden muss, beispielsweise in einer Disaster-Recovery-Situation.
* Die Wiederherstellung von Daten auf Blockebene erfolgt direkt an dem von Ihnen angegebenen Speicherort, wobei die ursprünglichen ACLs erhalten bleiben.
* In Dateikatalogen kann geblättert oder gesucht werden, um einzelne Ordner und Dateien für die Wiederherstellung auszuwählen.


Informationen zu Wiederherstellungsoptionen finden Sie unter link:prev-ontap-restore.html["Wiederherstellen von ONTAP -Volumes-Workloads"].



[[supported-volumes]]
== Unterstützte Volumes

NetApp Backup and Recovery unterstützt die folgenden Volumetypen:

* FlexVol Lese-/Schreib-Volumes
* FlexGroup Volumes (erfordert ONTAP 9.12.1 oder höher)
* SnapLock Enterprise Volumes (erfordert ONTAP 9.11.1 oder höher)
* SnapLock Compliance für lokale Volumes (erfordert ONTAP 9.14 oder höher)
* SnapMirror -Datenschutzzielvolumes (DP)



NOTE: NetApp Backup and Recovery unterstützt keine Sicherungen von FlexCache -Volumes.

Informationen zu den Quellsystemen, Sekundärsystemen, Objektspeicherzielen, Wiederherstellungszielen und Regionen, die von Backup and Recovery unterstützt werden, sind unter link:br-start-sources-destinations.html["Unterstützte Sicherungs- und Wiederherstellungsziele in NetApp Backup and Recovery"] aufgeführt. Zusätzliche Anforderungen und Einschränkungen sind unter link:br-reference-limitations.html["Bekannte Einschränkungen bei NetApp Backup and Recovery für ONTAP -Volumes"] aufgeführt.



[[cost-and-licensing]]
== Kosten und Lizenzierung

Für die Erstellung von Snapshots oder replizierten Volumes fallen außer dem von ihnen belegten Speicherplatz keine Kosten an. Ressourcengebühren Ihres Cloud-Anbieters und Servicegebühren von NetApp gelten nur für das Backup in Objektspeicher.

Nähere Informationen zu Kosten und Lizenzoptionen finden Sie in link:concept-backup-to-cloud.html#cost["Erfahren Sie mehr über NetApp Backup and Recovery"] und link:br-start-licensing.html["Lizenzierung einrichten"].
