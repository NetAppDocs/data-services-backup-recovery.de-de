= Oracle-Datenbank-Workloads mit NetApp Backup und Recovery klonen
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Mit NetApp Backup und Recovery lassen sich beschreibbare Klone von Oracle Datenbank-Workloads aus lokalen ONTAP Systemen auf primärem oder sekundärem Speicher erstellen. Auch eine zeitliche Planung der Klon-Aktualisierungen entsprechend den Anforderungen ist möglich.

*Erforderliche NetApp Console-Rolle* Backup and Recovery Super Admin oder Backup and Recovery Clone Admin Rolle. https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["Erfahren Sie mehr über die Zugriffsrollen der NetApp Console für alle Dienste"^].



[[create-a-clone-of-an-oracle-database]]
== Erstellen Sie einen Klon einer Oracle-Datenbank

Erstellen Sie sofort einen Klon aus einem vorhandenen Snapshot. Verwenden Sie diese Methode, um einen einmaligen Klon zu erstellen, der nicht kontinuierlich aus einem Snapshot aktualisiert wird.

.Schritte
. Wählen Sie im NetApp Console *Schutz > Sicherung und Wiederherstellung*.
. Wählen Sie unter *Workloads* die Kachel *Oracle* aus.
. Wählen Sie *Clone* aus.
. Wählen Sie *Neuen Klon erstellen*.
. Wählen Sie im Abschnitt *Datenbankquelle* den Quellhost und die Datenbank aus den Listen aus.
+
.. Wenn es sich bei der Quelldatenbank um eine Containerdatenbank (CDB) handelt, im Abschnitt *Klontyp* eine der folgenden Optionen auswählen:
+
*** *Vollständiger Datenbank-Clone*: Klont die gesamte Containerdatenbank, einschließlich aller PDBs.
*** *PDB-Klon*: Klont eine bestimmte PDB aus dem Container-Datenbank-Backup in eine bestehende Zielcontainerdatenbank.




. Im Abschnitt *Zieldatenbank* wählen Sie den Zielhost und die Datenbank aus den Listen aus. Der Zielhost und die Datenbank können sich vom Quellhost unterscheiden.
. Wählen Sie *Weiter*.
. Im Abschnitt *Klonen von* auf der Seite *Wiederherstellungspunkt auswählen* wählen Sie *Vorhandene Snapshots*.
. Wählen Sie einen vorhandenen Snapshot (Wiederherstellungspunkt) aus der Liste aus, um ihn als Basis für den Klon zu verwenden, und wählen Sie *Weiter*.
+
Die Seite *Speicherort für Snapshots auswählen* wird angezeigt, wenn der Snapshot an mehr als einem Speicherort gespeichert ist.

. Wählen Sie den Snapshot-Speicherort aus und wählen Sie *Weiter*.
. Führen Sie auf der Seite *Erweiterte Optionen* Folgendes aus:
+
.. Optional kann beim Klonen einer vollständigen mandantenfähigen Datenbank in den *Complete database clone settings* eine oder mehrere PDBs ausgewählt werden, die vom Klon ausgeschlossen werden sollen (PDB$SEED wird immer ausgeschlossen). Dieser Abschnitt erscheint beim Klonen einer Einzelmandantendatenbank nicht.
.. Wenn Sie zuvor eine Spezifikationsdatei gespeichert haben, kann die Option *Zieldatenbankparameter anpassen* aktiviert werden, um diese hochzuladen und die Einstellungen der geklonten Datenbank anzupassen. Es besteht außerdem die Möglichkeit, die Standardspezifikationsdatei für den Datenbank-Snapshot herunterzuladen.
.. Im Abschnitt *Wiederherstellungsbereich* kann eine Option zur Wiederherstellung des Klons mithilfe von Archivprotokollen ausgewählt und alle erforderlichen Details eingegeben werden. Die Auswahl von *Keine* überspringt die Wiederherstellung (der Klon wird aus dem Snapshot erstellt, ohne Änderungen aus den Archivprotokollen anzuwenden). *Keine* ist für PDB-Klone nicht verfügbar.
.. Im Abschnitt *Vor- und Nachskripte* können Sie eine oder beide der Optionen *Vorskript* und *Nachskript* aktivieren, um ein Skript auszuführen, bevor der Klonvorgang beginnt oder nachdem er abgeschlossen ist. Geben Sie für jede Option den vollständigen Skriptpfad und alle erforderlichen Argumente ein.


. Wählen Sie *Clone* aus.




[[schedule-a-clone-of-an-oracle-database]]
== Planen Sie das Klonen einer Oracle-Datenbank

Einen sofortigen Klon erstellen und regelmäßige Aktualisierungen planen, damit er dem aktuellen Stand der Datenbank entspricht.


NOTE: Das Erstellen eines sofortigen Snapshots und Klons mit einem Aktualisierungszeitplan gilt nur für vollständige Datenbankklone. Es ist nicht für einen PDB-Klon verfügbar.

.Schritte
. Wählen Sie im NetApp Console *Schutz > Sicherung und Wiederherstellung*.
. Wählen Sie unter *Workloads* die Kachel *Oracle* aus.
. Wählen Sie *Clone* aus.
. Wählen Sie *Neuen Klon erstellen*.
. Wählen Sie im Abschnitt *Datenbankquelle* den Quellhost und die Datenbank aus den Listen aus.
. Im Abschnitt *Zieldatenbank* wählen Sie den Zielhost und die Datenbank aus den Listen aus. Der Zielhost und die Datenbank können sich vom Quellhost unterscheiden.
. Wählen Sie *Weiter*.
. Im Abschnitt *Klonen von* auf der Seite *Wiederherstellungspunkt auswählen* wählen Sie *Instant snapshot and clone*.
. Wählen Sie einen Speicherort für den Snapshot, wenn er erstellt wird.
. Wählen Sie *Weiter*.
. Führen Sie auf der Seite *Erweiterte Optionen* Folgendes aus:
+
.. Um die Einstellungen der geklonten Datenbank anzupassen, aktivieren Sie die Option *Zieldatenbankparameter anpassen*. Wenn Sie zuvor eine Spezifikationsdatei gespeichert haben, können Sie diese mit dieser Option hochladen, um die Einstellungen der geklonten Datenbank anzupassen. Sie können auch die Standardspezifikationsdatei für die Datenbank herunterladen, die deren aktuelle Einstellungen widerspiegelt.
.. Im Abschnitt *Aktualisierungszeitplan für den Klon* wird festgelegt, wann und wie oft der Klon aktualisiert wird. Die Aktualisierung aktualisiert den Instant-Snapshot und überschreibt den bestehenden Klon mit einer neuen Kopie.
.. Im Abschnitt *Vor- und Nachskripte* können Sie eine oder beide der Optionen *Vorskript* und *Nachskript* aktivieren, um ein Skript auszuführen, bevor der Klonvorgang beginnt oder nachdem er abgeschlossen ist. Geben Sie für jede Option den vollständigen Skriptpfad und alle erforderlichen Argumente ein.


. Wählen Sie *Clone* aus.




[[split-a-clone]]
== Einen Klon teilen

Sie können einen Klon Ihrer Oracle Database-Workloads aufteilen, um eine unabhängige oder langfristige Kopie zu erstellen. Das Aufteilen eines Klons erstellt ein neues Backup aus dem Klon, das für Schutz- und Wiederherstellungsvorgänge verwendet werden kann.

Der Aufteilungsvorgang zeigt die Aggregate, die Teil der Storage-VM sind, deren Größen sowie den Speicherort des geklonten Volumes an. NetApp Backup and Recovery gibt an, ob ausreichend Speicherplatz vorhanden ist, um die Aufteilung abzuschließen. Nach der Aufteilung ist der Klon unabhängig. Der ursprüngliche Klonauftrag bleibt für zukünftige Vorgänge verfügbar.

.Schritte
. Wählen Sie im NetApp Backup and Recovery -Menü *Klonen* aus.
. Wählen Sie einen Klon aus.
. Wählen Sie das Symbol Aktionenimage:../media/icon-action.png["Aktionsoption"] > *Geteilter Klon*.
. Überprüfen Sie die Details zum geteilten Klon und wählen Sie *Teilen*.
. Wenn der geteilte Klon erstellt ist, können Sie ihn auf der Seite *Inventar* anzeigen.




[[delete-a-clone]]
== Löschen eines Klons

Klone von Oracle Database Workloads können entfernt werden, um Speicherplatz freizugeben. Wenn eine Richtlinie den Klon schützt, werden sowohl der Klon als auch der zugehörige Job gelöscht.

.Schritte
. Wählen Sie im NetApp Backup and Recovery -Menü *Klonen* aus.
. Wählen Sie einen Klon aus.
. Wählen Sie das Symbol Aktionenimage:../media/icon-action.png["Aktionsoption"] > *Klon löschen*.
. Im Bestätigungsdialogfeld „Klon löschen“ werden die Details des Löschvorgangs angezeigt.
+
.. Um die geklonten Ressourcen aus SnapCenter zu löschen, auch wenn auf die Klone oder ihren Speicher nicht zugegriffen werden kann, wählen Sie *Löschen erzwingen*.
.. Wählen Sie *Löschen*.


. Wenn der Klon gelöscht wird, wird er von der Seite *Inventar* entfernt.
